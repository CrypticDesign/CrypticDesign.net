- Canonical decorative palette, semantic status colors, route identity, existing gameplay canon, and authentication/admission boundaries remain unchanged.

## Release procedure

1. Commit only this task's implementation, tests, documentation, and responsive evidence. Exclude unrelated community evidence files and `debug.log`.
2. Push `codex/responsive-nav-20260826`, open one PR against `main`, and require the configured deploy-preview checks to pass.
3. Merge once under Robert's release approval. This triggers the configured Netlify production build for the demo; do not push directly to main or issue duplicate deploy requests.
4. Verify the deployment/check status and live demo route/navigation behavior before marking it deployed in Jira/Confluence.

## Rollback and scope boundary

Baseline main: `719ae4d5051e8b8a3cef65f26f6112ff27691f0a` (merged PR #57). The new release contains only the responsive delta from that tree.

Escalate/roll back the demo if front doors repeatedly return 5xx, primary navigation becomes inaccessible, mobile layout clips critical actions, or the embedded game cannot exit fullscreen. Preferred recovery is restoration of the last successful demo deployment for this baseline; a reviewed revert PR is the Git recovery path. Do not change DNS or unrelated provider settings.

Release commit, PR, deployment URL, live verification, and remaining acceptance will be recorded in CRY-355, CRY-495 and the current Consumer Experience / Prismatic VDS Confluence page after publication. Broader launch/cutover issues must not be closed solely because this demo release succeeds.
