Date: 2026-09-07 (America/Chicago)  
Candidate source: `ba7fca00eb6bc25ec98d8ba2e794e437cd4bea8e`  
Target: `https://demo.crypticdesign.net`  
Disposition: **PASS WITH NON-BLOCKING FOLLOW-UPS**

## Results

- 60 direct-route checks passed: 15 launch-representative routes/assets × browser, Googlebot, Bingbot, and Slackbot user agents.
- No unintended crawler blocking, auth challenge, or user-agent-specific status difference was observed.
- Eight representative redirect checks passed with their intended destinations. Temporary compatibility redirects returned 307; permanent legacy redirects returned 308.
- `robots.txt`, `sitemap.xml`, the Home share image, nested routes, Request Access, and Sign In all returned HTTP 200.
- Netlify served HTTPS with `Strict-Transport-Security: max-age=31536000` and `X-Content-Type-Options: nosniff`.
- Dynamic HTML used `Cache-Control: private,no-cache,no-store,max-age=0,must-revalidate`, `Age: 0`, and an appropriate Next.js `Vary` header. This favors freshness over shared-edge caching for HTML.
- No `netlify.toml` or repository-owned Netlify edge-function directory exists in current main. Redirects are application-owned in `next.config.ts`; provider-side domain/access controls still require operator inspection.

## Follow-up hardening

The demo root response did not include:

- `Content-Security-Policy`
- `X-Frame-Options` (or an equivalent CSP `frame-ancestors` policy)
- `Referrer-Policy`
- `Permissions-Policy`

These are defense-in-depth gaps. No active exploit, unintended exposure, or launch-path failure was demonstrated by this audit, so they are recorded as non-blocking follow-ups rather than CRY-320 blockers.
